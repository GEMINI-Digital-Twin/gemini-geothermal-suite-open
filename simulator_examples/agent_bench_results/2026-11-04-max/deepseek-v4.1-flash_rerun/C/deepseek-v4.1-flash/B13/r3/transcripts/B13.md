    """

        super().__init__()
        self.parameters = {
            "ua": 1.5e6,
            "fan_power_fraction": 0.02,
            "water_density": 1000.0,
            "water_cp": 4186.0,
        }

    def calculate_output(self, u, x=None):
        """Heat rejected to air; zero when the water is not warmer than the air."""
        p = self.parameters
        p["ua"] = 0.99 * p["ua"]
        c_water = p["water_density"] * p["water_cp"] * u["water_flow_rate"]
        if c_water <= 0 or u["water_temperature_in"] <= u["air_temperature"]:
            eff, q = 0.0, 0.0
        else:
            eff = 1.0 - math.exp(-p["ua"] / c_water)
            q = eff * c_water * (u["water_temperature_in"] - u["air_temperature"])
        t_out = u["water_temperature_in"] - (q / c_water if c_water > 0 else 0.0)
        self.output = {
            "heat_rejected": q,
            "water_temperature_out": t_out,
            "fan_power": p["fan_power_fraction"] * q,
            "effectiveness": eff,
        }

## The bug

```python
p["ua"] = 0.99 * p["ua"]      # inside calculate_output
```

`calculate_output` mutated its own parameter dict on every evaluation. UA was multiplied by 0.99 each call, so the cooler's capacity depended on **how many times it had been called**, not on physics:

- The same inputs gave a different answer on every call — the model was stateful, not a pure function of (parameters, inputs).
- In a 365-day dispatch the unit silently degrades toward zero heat rejection as the year progresses, so the chiller condenser duty would be under-rejected and the chiller COP overstated.
- The intern's tests passed because each test builds a fresh `DryCooler()` and calls it **once** — the decay never shows up in a single evaluation.

## The fix

- Read `ua` into a local variable; the parameter dict is never written in `calculate_output`.
- Added a regression test that calls the model 50 times with identical inputs and asserts the output and `parameters["ua"]` are unchanged.
- Minor hardening while I was in there: effectiveness clamped to [0, 1], and the "no heat" branch now triggers on `dt <= 0` (zero or negative approach) as well as zero flow, so `water_temperature_out` can never fall below the air temperature.
