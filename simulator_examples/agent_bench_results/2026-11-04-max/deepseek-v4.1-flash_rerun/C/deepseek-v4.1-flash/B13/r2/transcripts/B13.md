    ``air_temperature`` (degC). Outputs: ``heat_rejected`` (W),
    ``water_temperature_out`` (degC), ``fan_power`` (W), ``effectiveness``.
    """

        """Defaults for a 10 MW unit."""
        super().__init__()
        self.parameters = {
            "ua": 1.5e6,
            "fan_power_fraction": 0.02,
            "water_density": 1000.0,
            "water_cp": 4186.0,
        }

    def calculate_output(self, u, x=None):
        """Heat rejected to air; zero when the water is not warmer than the air."""
        p = self.parameters
        c_water = p["water_density"] * p["water_cp"] * u["water_flow_rate"]
        if c_water <= 0 or u["water_temperature_in"] <= u["air_temperature"]:
            eff, q = 0.0, 0.0
        else:

            q = eff * c_water * (u["water_temperature_in"] - u["air_temperature"])

        self.output = {
            "heat_rejected": q,
            "water_temperature_out": t_out,
            "fan_power": p["fan_power_fraction"] * q,
            "effectiveness": eff,
        }

**The bug:** the effectiveness was multiplied by a fudge factor of 1.3:

```python
eff = 1.3 * (1.0 - math.exp(-p["ua"] / c_water))
```

The plain NTU result `1 - exp(-UA/C_water)` is already the correct effectiveness for a water-to-air cooler with the air treated as an infinite sink (C_r = 0). Multiplying it by 1.3 breaks two things:

1. **Second-law violation.** At low water flow, NTU = UA/C_water is large, so `1 - exp(-NTU)` approaches 1 and 1.3× pushes effectiveness above 1. The outlet temperature then falls *below* the air temperature — the cooler would be rejecting heat to a warmer sink. With the model's own defaults (ua = 1.5e6 W/K) this happens as soon as the water flow drops well below the 0.3 m3/s design point, i.e. exactly in part-load operation.
2. **Inflated heat rejection.** Even where effectiveness stays below 1, the 1.3 factor overstates heat rejected by 30 %, which flatters any chiller/condenser design that uses this model.

The intern's tests missed it because they only ran one operating point (0.3 m3/s, 38 °C in, 25 °C air), where the inflated effectiveness still happens to land below 1 — so the "outlet between air and inlet" and "effectiveness < 1" assertions passed by luck.

**The fix:** plain `eff = 1 - exp(-UA/C_water)`, clamped to [0, 1], plus a clamp of the outlet to [air temperature, inlet temperature] and a recomputation of `heat_rejected` from the clamped outlet so the energy balance stays exact. Zero flow and air-not-colder cases return zero heat, zero fan power and the inlet temperature unchanged.

I added regression tests that sweep low flows (0.01–0.6 m3/s) and assert effectiveness stays in [0, 1] and the outlet never drops below the air temperature, plus monotonicity checks (heat rises with inlet temperature and flow, falls with air temperature) and the fan-power bound. The lesson is saved to project memory so the same fudge factor doesn't come back.

Note: this standalone model is not what the `screw_dry_cooler` chiller option uses internally — that option has its own fixed condenser approach — so registering it does not by itself change any plant design run.
